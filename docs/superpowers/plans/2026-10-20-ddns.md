# DDNS Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-profile dynamic DNS client for IPv4. The public IP comes from a quorum of three HTTPS sources, and updates go to a generic one-request HTTPS provider template. Status is shown in the web UI and served over SNMP via NET-SNMP-EXTEND-MIB.

**Architecture:**
- **New component `components/ddns`.** It has a pure-C core (`ddns_core.c`), which has no ESP-IDF includes and is unit-tested on the host with gcc. It also has an ESP-IDF runtime (`ddns.c`), which owns the task, HTTP, NVS, events and status.
- **Wiring into `main` is thin:** `main.c` (init + platform callbacks), `web_ui.c` (3 handlers + status), `index.html` (DDNS tab) and `ota.c` (busy flag).
- **SNMP** is reached through a callback that DDNS registers with `snmp_agent`, so `snmp_agent` never depends on `ddns`.

**Tech Stack:** ESP-IDF 5.5.3 via PlatformIO (`pio run -e esp32-s3`), FreeRTOS, `esp_http_client` + `esp_crt_bundle`, `http_parser`, cJSON, NVS, lwIP `getaddrinfo`. Host tests use gcc and a Makefile.

**Spec:** `docs/superpowers/specs/2026-10-20-ddns-design.md` (approved). Read it first; this plan argues from it and doesn't repeat its rationale.

## Global Constraints

- **Branch `feat/ddns` on the fork.** The spec and this plan stay on the fork; they are not part of the upstream PR.
- **Upstream-clean.** `components/ddns/**` and the `snmp_agent` changes must not reference any W5500, `eth_uplink`, `eth_connect`, `sta_connect` or `netif_is_uplink` symbol. Only `main.c`, `web_ui.c` and `index.html` wiring may differ between branches.
- **No `sdkconfig*` changes.** HTTP Basic auth is built in code. Certificate dates stay unchecked (`CONFIG_MBEDTLS_HAVE_TIME_DATE` off) and that is documented.
- **Off by default.** While disabled the feature makes no network traffic.
- **The DDNS task never calls NVS or flash APIs.** Its stack is in PSRAM. The one write it needs (`ddns_stop`) is done by an `esp_timer` one-shot callback.
- **Style and checks.** clang-format 18 (LLVM, 4 spaces, 120 columns) on changed lines, and cppcheck clean.
- **No secrets in logs.** No template, filled-in request, response body, password or token is ever passed to `ESP_LOG*`. The log default level is WARN, but rule this out at every level.
- **Limits:**

  | Item | Limit |
  |---|---|
  | URL template | ≤ 256 B |
  | Header template | ≤ 256 B |
  | Body template | ≤ 512 B |
  | User | ≤ 64 |
  | Password | ≤ 128 |
  | Token | ≤ 128 |
  | Success match | ≤ 64 |
  | Custom source URL | ≤ 128 |
  | Filled-in URL | ≤ 512 |
  | Filled-in header line | ≤ 512 |
  | Filled-in body | ≤ 1024 |
  | Response read | 1024 B |
  | IP answer | ≤ 64 B |
  | UI snippet | ≤ 64 printable ASCII |
  | Interval | 1–1440 min, default 5 |
  | Refresh | 0–365 days, default 0 |

- **Timings:**

  | Item | Value |
  |---|---|
  | WAN-up delay | 10 s |
  | Re-check while the clock isn't synced | 60 s |
  | Time synced when | `time(NULL) >= 1700000000` |
  | Per-request budget | 20 s total |
  | Connect/read timeout | 10 s |
  | Provider calls | at most one per 60 s |
  | 429 | `Retry-After` seconds capped at 86400, else 600 s |
  | `dnserr`/`911` | 1800 s |
  | Back-off | starts at the interval, doubles, capped at 3600 s |
  | Force | at most once per 60 s |

- **Default sources:** ipify, icanhazip, AWS checkip. Presets:
  - `https://api.ipify.org`
  - `https://ipv4.icanhazip.com`
  - `https://checkip.amazonaws.com`
  - `https://ifconfig.me/ip`
- **NVS:** namespace `"tsr"`, key `ddns_cfg` (one blob, `version` = 1) and key `ddns_stop` (string reason).
- **SNMP:**
  - extend row index `"ddns"` = `4.100.100.110.115`
  - `MAX_OID` = 24
  - the private `99999` tree is unchanged
- **Web handler slots:** at most 3 new (`GET /api/ddns`, `POST /api/ddns`, `POST /api/ddns/force`).
- **Commits:** local commits only; no pushes or PRs until the user asks.

## Review Focus

1. **The WAN drops or fails over while a check is between "IP agreed" and "request sent".** No request goes out with the old uplink's IP; the queued rerun takes over. Pinned in Task 5: `test_sched_epoch_change_blocks_send`.
2. **Settings are saved while a provider request is in flight.** The result doesn't overwrite status for the new settings, but a 429 or dnserr cooldown from that request still applies. Pinned in Task 5: `test_sched_stale_generation_still_records_cooldown`.
3. **A password or token with special characters** (`&`, `%`, `+`, `"`, `\`, `:`, `@`, space, UTF-8 bytes). The URL and form get correct percent-encoding, the JSON gets escaping, Basic auth works with a `:` in the password, and the snippet is still redacted. Pinned in Task 2: `test_fill_special_chars_all_contexts`. Pinned in Task 4: `test_redact_encoded_forms`.
4. **The clock is unsynced at boot, or jumps backwards after a success.** No check runs before sync, and refresh doesn't fire early or get stuck. Pinned in Task 5: `test_sched_refresh_clock_backwards`.
5. **A reboot loop after `badauth`.** The device doesn't call the provider again after reboot; the status says "stopped". Pinned in Task 6: `test_stop_reason_survives_reload`, and checked on the device in Task 10, step 4.

**Interfaces:**
- Produces, in `ddns_core.h`:
  - `bool ddns_ipv4_parse(const char *s, size_t n, uint32_t *out)`
    - accepts exactly four decimal octets, each 0–255;
    - rejects leading zeros except a lone `0`, any sign, and any trailing byte;
    - `*out` is in host order.
  - `bool ddns_ipv4_is_public(uint32_t ip)`
    - false for `0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16`, `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.88.99/24`, `192.168/16`, `198.18/15`, `198.51.100/24`, `203.0.113/24`, `224/4` and `240/4` (including `255.255.255.255`).
  - `bool ddns_parse_ip_answer(int http_status, const char *body, size_t len, uint32_t *ip)`
    - 2xx only; `len <= 64`;
    - leading and trailing ASCII whitespace (space, `\t`, `\r`, `\n`) is trimmed;
    - any other byte below 0x20, or 0x7f, makes it fail;
    - the result must be a public IPv4 address.
  - `typedef enum { DDNS_Q_AGREE, DDNS_Q_ASK_SLOT3, DDNS_Q_FAIL } ddns_quorum_t;`
  - `ddns_quorum_t ddns_quorum(const bool ok[3], const uint32_t ip[3], bool slot3_asked, uint32_t *out)`
    - before slot 3 is asked: AGREE if `ok[0] && ok[1] && ip[0]==ip[1]`, otherwise ASK_SLOT3;
    - after slot 3 is asked: AGREE if any two `ok` slots hold equal IPs, otherwise FAIL.
  - `void ddns_wipe(void *p, size_t n)`: a volatile-pointer memset that the compiler can't optimise away.

- Produces, in `ddns_core.h`. Field sizes include the NUL; every later task uses these exact names.

  ```c
      uint8_t  method, body_type;          /* ddns_method_t / ddns_body_type_t */
      uint16_t interval_min, refresh_days;

      char user[65], pass[129], token[129], match[65];
      struct { uint8_t kind; char custom[129]; } src[3];
  } ddns_cfg_t;
  void ddns_cfg_defaults(ddns_cfg_t *c);    /* disabled, GET, form, interval 5, wan_trigger on, refresh 0, sources IPIFY/ICANHAZIP/AWS */
  const char *ddns_src_url(const ddns_cfg_t *c, int slot);   /* preset URL or custom */

  typedef enum { DDNS_OK = 0, DDNS_E_TOO_LONG, DDNS_E_PLACEHOLDER, DDNS_E_HEADER, DDNS_E_JSON,
                 DDNS_E_URL, DDNS_E_NO_IP, DDNS_E_SECRET_LITERAL, DDNS_E_SCHEME, DDNS_E_SOURCES,
                 DDNS_E_RANGE, DDNS_E_BODY_WITH_GET } ddns_err_t;
  const char *ddns_err_str(ddns_err_t e);   /* short English text, safe to log */

  typedef struct {
      char url[513];
      char hdr_name[64], hdr_value[449];   /* hdr_name + ": " + hdr_value <= 512 */
      char body[1025];
      char auth[300];                      /* full "Basic …"; empty = none */
      bool has_header;
  } ddns_req_t;
  ddns_err_t ddns_fill(const ddns_cfg_t *c, uint32_t ip, ddns_req_t *out);
  size_t ddns_base64(const uint8_t *in, size_t n, char *out, size_t out_sz);  /* returns length or 0 when out too small */
  ```
- **Placeholder rules for `ddns_fill`:**
  - The tokens are `{ip}`, `{user}`, `{pass}` and `{token}`. Any other `{…}` → `DDNS_E_PLACEHOLDER`.
  - Each placeholder is filled exactly once, in a single left-to-right pass. Inserted text is never scanned again.
  - Encoding by context:

    | Where | `{ip}` | `{user}`/`{pass}`/`{token}` |
    |---|---|---|
    | URL | verbatim dotted quad | RFC 3986 percent-encoded; only `A–Z a–z 0–9 - . _ ~` left as is |
    | Header | verbatim | verbatim |
    | Form body | verbatim | percent-encoded |
    | JSON body | verbatim | JSON-string-escaped (`"` `\` and controls as `\u00XX`) |

  - **URL placement.** Placeholders are allowed only after `https://`, in userinfo, path or query. One in the host or port → `DDNS_E_PLACEHOLDER`.
  - **JSON placement.** Placeholders are allowed only inside string literals. Track whether the template is in a string, honouring backslash escapes.
  - **Basic auth.**
    - A URL starting `https://{user}:{pass}@` has that userinfo removed from `out->url`, and `auth` is set from the user and password.
    - Otherwise, when both `user` and `pass` are non-empty, `auth` is set the same way.
    - `auth` stays empty when the header name is `Authorization` (case-insensitive).
  - **Filled-in checks.**
    - The header splits at the first `:`, with the value's leading spaces trimmed.
    - The name must be RFC 7230 token characters.
    - The value must have no byte below 0x20 except tab, and no 0x7f.
    - The name must not be `Host`, `Content-Length`, `Transfer-Encoding`, `Connection` or `Cookie` (case-insensitive).
    - Failing any of these → `DDNS_E_HEADER`.
    - A JSON body is checked by `bool ddns_json_valid(const char *s)`, a small recursive-descent validator capped at nesting depth 8. Failure → `DDNS_E_JSON`. This keeps the core free of cJSON.
  - **Caps.** All size math uses `size_t`, with bounds checked before each append. Exceeding a cap → `DDNS_E_TOO_LONG`.
  - **Wiping.** On any error, `out` is wiped.

### Task 3: Save-time validation, normalisation and fingerprint

**Files:**
- Modify: `components/ddns/ddns_core.h`
- Modify: `components/ddns/ddns_core.c`
- Modify: `tools/ddns_host_test/test_ddns_core.c`

**Interfaces:**
- Consumes: `ddns_cfg_t`, `ddns_fill`, `ddns_ipv4_parse`, `ddns_ipv4_is_public` (Tasks 1–2).
- Produces:
  - `ddns_err_t ddns_cfg_validate(ddns_cfg_t *c, char *msg, size_t msg_sz)`
    - It normalises `c` in place, then validates it.
    - On success it returns `DDNS_OK`.
    - On failure it leaves a one-sentence, user-facing reason in `msg` that never contains a secret value.
  - `uint64_t ddns_cfg_fingerprint(const ddns_cfg_t *c)`
    - FNV-1a 64 over `url`, `method`, `header`, `body`, `body_type`, `src_ip`, `user`, `pass` and `token`. Each string is hashed with its NUL so field boundaries are unambiguous.
    - Not over `match`, the sources or the timings.
  - `bool ddns_url_host(const char *url, char *host, size_t host_sz)`
    - Takes the host from an `http(s)://` URL, skipping userinfo and stopping at `:`, `/`, `?` or `#`.
    - This is the only URL-derived string allowed in logs, SNMP and status.
- **Rules, in order:**
  1. **Ranges.**
     - `interval_min` must be 1–1440, `refresh_days` 0–365, `method` ≤ PATCH and `body_type` ≤ JSON. Otherwise `DDNS_E_RANGE`.
     - `src[i].kind` must be ≤ CUSTOM. Otherwise `DDNS_E_SOURCES`.
  2. **Userinfo.**
     - If `url` has a literal `user:pass@` (not `{user}:{pass}@`), percent-decode both parts into `user`/`pass`.
     - Then rewrite the URL to `https://{user}:{pass}@…`.
     - If the decoded parts don't fit their fields → `DDNS_E_TOO_LONG`.
  3. **Provider scheme.** `url` must start with `https://`. Otherwise `DDNS_E_SCHEME`.
  4. **Sources.**
     - The three resolved source URLs must be pairwise different (exact string compare after `ddns_src_url`).
     - At most one may start with `http://`.
     - Each custom URL must start with `http://` or `https://`.
     - If a custom host is a literal IPv4 address, it must be public. This is the save-time half of the destination policy; the runtime half is in Task 6.
     - Any failure → `DDNS_E_SOURCES`.
  5. **Literal secrets.**
     - Any of these query/form parameters or JSON keys with a non-empty literal value (no `{` in the value) → `DDNS_E_SECRET_LITERAL`: `token`, `key`, `password`, `pass`, `pwd`, `secret`, `apikey` and `secretapikey` (case-insensitive), and `q` (case-sensitive).
     - Likewise a header whose name contains `auth`, `key`, `token` or `secret` (case-insensitive) and whose value has no placeholder.
  6. **Body with GET.** A non-empty `body` with `method == DDNS_M_GET` → `DDNS_E_BODY_WITH_GET`.
  7. **`{ip}` required.** Unless `src_ip` is set, `{ip}` must appear in the URL, header or body. Otherwise `DDNS_E_NO_IP`.
  8. **Dry run.**
     - Run `ddns_fill` with ip `1.2.3.4`.
     - Replace the user, password and token with `x` repeated to their stored lengths, so the length caps apply realistically.
     - Pass through any error.
     - Wipe the dry-run `ddns_req_t` afterwards.

  ```c
                                  uint32_t gen_at_start, uint32_t gen_now,
                                  uint32_t epoch_at_start, uint32_t epoch_now);

  /* Apply a provider outcome. same_gen = config generation unchanged since dispatch. */
  void    ddns_sched_on_result(ddns_sched_t *s, const ddns_class_t *r, bool same_gen, int64_t now_us,
                               int64_t wall_now, uint32_t ip, uint64_t fp, uint16_t interval_min);
  void    ddns_sched_on_config_saved(ddns_sched_t *s);   /* clears stopped, back-off and force_pending; keeps cooldown and last_attempt */
  ```

- **`want_send`.**
  - It returns false when `stopped` is set and no force is pending.
  - Otherwise it returns true when any of these holds:
    - `force_pending` is set;
    - `!have_ok`;
    - `ip != ok_ip` or `fp != ok_fp`;
    - a refresh is due: `refresh_days > 0`, and `wall_now - min(ok_wall, wall_now) >= refresh_days*86400`.
  - Clock jumping backwards: the clamp means `ok_wall` is treated as `wall_now`. Task 6 also rewrites `ok_wall` to `wall_now` when it sees `ok_wall > wall_now`, so refresh restarts its count.
- **`may_dispatch`** returns true only when all of these hold:
  - `now_us >= provider_ready_us`;
  - `gen_now == gen_at_start`;
  - `epoch_now == epoch_at_start`.
- **`on_result`.**

  - SUCCESS and STOPPED change the last-success fields or `stopped` only when `same_gen` is true.

    - **STOPPED:** set `stopped` and `stop_reason`.
    - **COOLDOWN:** `cooldown_until = now + cooldown_s`.
    - **REDIRECT/TEMP:** `backoff_s = backoff_s ? min(2*backoff_s, 3600) : max(60, min(interval_min*60, 3600))`, then `backoff_until = now + backoff_s`.
  - A forced check during a cooldown keeps `force_pending` and doesn't dispatch until the cooldown ends.

- **`line1` formats:**
  - `ok <quorum ip>`
  - `disabled`
  - `waiting <detail>`
  - `quorum-failed`
  - `provider-error <detail>`
  - `cooldown <detail>`
  - `stopped <reason>`
- **`full`** is newline-separated lines and at most 255 bytes:
  - `src1 <ip|err>`, `src2 …`, `src3 …` (`-` when not asked)
  - `last_ok <ip> <ISO-8601 UTC or ->`
  - `last_http <n> <error>`

  It never contains the snippet. `num_lines` counts these lines.
- **Rows** go in `s_mib` immediately before the `99999` row, in this order:
  - `1.3.6.1.4.1.8072.1.3.2.1.0`: INT32 = 1
  - `….2.2.1.{2,3,4,5,6,7,20,21}.4.100.100.110.115`:

    | Column | Type | Value |
    |---|---|---|
    | 2 | STRING | `"ddns"` |
    | 3 | STRING | `""` |
    | 4 | STRING | `""` |
    | 5 | INT32 | 0 |
    | 6 | INT32 | 1 |
    | 7 | INT32 | 1 |
    | 20 | INT32 | 5 |
    | 21 | INT32 | 1 |

  - `….2.3.1.{1,2,3,4}.4.100.100.110.115`:

    | Column | Type | Value |
    |---|---|---|
    | 1 | STRING | `line1` |
    | 2 | STRING | `full` |
    | 3 | INT32 | `num_lines` |
    | 4 | INT32 | `result` |

- **Snapshot.**
  - A static `snmp_extend_snapshot_t s_ext` plus `bool s_ext_fresh`.
  - `process_pdu` clears `s_ext_fresh` at entry.
  - Each extend getter calls `ext_snapshot()`, which fills `s_ext` once per PDU from the callback, or uses `"disabled"`/1 with no callback.
  - `MAX_OID` becomes 24. Confirm `VB_BUF` 320 still fits an 18-arc OID plus a 255-byte string. If it doesn't, raise it and note why in the comment.
  - The existing order check at init must not log.

    ```json
    {"enabled":false,"url":"","method":"GET","header":"","body":"","body_type":"form",
     "src_ip":false,"user":"","pass_set":false,"pass_len":0,"token_set":false,"token_len":0,
     "match":"","sources":[{"preset":"ipify","url":""},{"preset":"icanhazip","url":""},{"preset":"aws","url":""}],

     "status":{"state":"disabled","detail":"","provider_host":"","sources":[{"asked":false,"ok":false,"ip":"","error":""},…],

    ```
    - Preset names: `ipify`, `icanhazip`, `aws`, `ifconfig`, `custom`.
    - State names, matching `ddns_state_t`: `disabled`, `waiting`, `ok`, `quorum-failed`, `provider-error`, `cooldown`, `stopped`.
  - **`POST /api/ddns`**
    - Takes the same keys, all optional and seeded from the current config.
    - Adds `"pass"` and `"token"`: an absent or empty value means keep. `"pass_clear"` and `"token_clear"` are booleans.
    - Responses:
      - 200 `{"ok":true}`
      - 400 `{"error":"<msg from ddns_save_config>"}`
      - 415 when the content type isn't JSON
      - 500 `{"error":"could not save (NVS)"}`
  - **`POST /api/ddns/force`**
    - Must be JSON (any body, `{}` is enough).
    - Responses: 200 `{"queued":true}` or `{"queued":false,"wait_s":N}`.
  - **`/api/status`** gains `"ddns":{"state":…,"provider_host":…,"quorum_ip":…,"last_ok_age_s":…}`.
- **JSON-only guard.**
  - `static bool require_json(httpd_req_t *req)`. It reads `Content-Type` with `httpd_req_get_hdr_value_str`.
  - It accepts a value starting with `application/json` (case-insensitive). Otherwise it sends `415 Unsupported Media Type` and returns false.
  - It runs after `require_auth` on both POSTs.
- **Buffers.**
  - Request bodies use `malloc_body_buf(8192)` + `recv_body`, as `snmp_post_handler` does.
  - The `ddns_cfg_t` and `ddns_status_t` used by handlers come from `heap_caps_calloc(…, MALLOC_CAP_SPIRAM)`, not the httpd stack.
  - The parsed cJSON tree and every string that held a secret are wiped before freeing: walk the `pass`/`token` items and `ddns_wipe` their `valuestring`.
- **Secrets are never written to responses.** `pass` and `token` are never returned. `user` is returned, because the spec doesn't treat it as a secret.
