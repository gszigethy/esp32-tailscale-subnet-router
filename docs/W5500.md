# W5500 Ethernet fork

This fork is [Csontikka/esp32-tailscale-subnet-router](https://github.com/Csontikka/esp32-tailscale-subnet-router)
plus one feature: a **wired uplink through a WIZnet W5500 SPI Ethernet module**.
Everything else (SNMP, the web UI, the tunnel, telemetry, the rest of the docs)
is upstream's, unchanged. The upstream [README](../README.md),
[CONFIGURATION](CONFIGURATION.md) and [CHANGELOG](../CHANGELOG.md) apply as
written; this page covers only what the fork adds.

## What it does

- **Ethernet becomes the uplink when a W5500 is present.** The module is probed
  at boot. Once it holds a DHCP lease it is promoted to the default route and
  the tunnel reconnects over it. With no module fitted the firmware runs
  exactly like upstream on WiFi.
- **WiFi uplink is optional.** A wired device can leave the WiFi STA off and run
  the radio as an access point only.
- **Every uplink-dependent path works on either uplink:**
  - exit-node and LAN-bypass routing,
  - the Source-NAT for advertised routes,
  - the firewall's Internet-side chains (`TO_ESP` / `FROM_ESP`),
  - the TTL override,
  - DNS handed to AP clients,
  - port mappings,
  - telemetry's "uplink is up" wait.
- **Per-interface subnet advertisement.** On top of upstream's AP subnet and
  manual route list, the Ethernet LAN (on by default) and the WiFi STA LAN
  (off by default) can each be advertised with one toggle.
- **Ethernet status** on the Status page: address, gateway, DNS, MAC and
  traffic counters.

## Hardware

The defaults match a **Seeed XIAO ESP32-S3** with the **XIAO W5500 Ethernet
adapter**. Pins are set in `idf.py menuconfig` → *W5500 Ethernet Uplink*:

| Signal | Kconfig | Default | XIAO pin |
|---|---|---|---|
| CS   | `ETH_W5500_CS_GPIO`   | GPIO2  | D1 |
| SCK  | `ETH_W5500_SCK_GPIO`  | GPIO7  | D8 |
| MISO | `ETH_W5500_MISO_GPIO` | GPIO8  | D9 |
| MOSI | `ETH_W5500_MOSI_GPIO` | GPIO9  | D10 |
| INT  | `ETH_W5500_INT_GPIO`  | -1 (10 ms polling) | GPIO16 if wired |

`ETH_W5500_SPI_HOST` (default SPI2) and `ETH_W5500_SPI_CLOCK_MHZ` (default 20)
are there too. Setting `ETH_W5500_ENABLED=n` builds a firmware without the
Ethernet driver.

The W5500 uses the fork's own SPI transport (`w5500_xfer_*` in
`main/eth_uplink.c`) instead of ESP-IDF's stock one. The stock transport
makes the SPI driver allocate a temporary DMA buffer for almost every
transfer. If one of those allocations fails, which happens when internal RAM
runs short during an OTA download, ESP-IDF's error path dereferences NULL and
`w5500_tsk` panics. The fork's transport allocates its two buffers once, at
startup, so nothing is allocated per transfer.

`main/linker.lf` (the driver's hot path in IRAM) dates from an earlier, wrong
diagnosis of that same crash. It is harmless, and is kept until beta2 has
been confirmed.

## Status page controls

**Use as uplink** switches, one on each uplink card. They apply immediately,
with no reboot:

| Card | Default | When off |
|---|---|---|
| Ethernet Uplink | **on** | Driver stopped (no link, no lease), but kept installed so it restarts at once. The card reads *Disabled*. |
| Uplink WiFi | **off** on a fresh board, **on** if WiFi networks were already saved | STA never associates, so the radio stops scanning against a placeholder SSID. The soft-AP is unaffected. |

**Auto-route** toggles, one on each uplink card, add that interface's subnet to
the advertised routes:

| Interface | Default | Notes |
|---|---|---|
| Ethernet | **on** | CIDR cached on the first DHCP lease, refreshed when the address changes. |
| WiFi STA | **off** | When enabled, the CIDR is read from the live connection straight away. |

- **AP subnet:** stays on upstream's *Advertise the AP subnet* switch on the
  Tailscale card.
- **Manual routes:** the manual route list is never modified.
- **Merging:** all sources are merged and de-duplicated at connect time.
- **Preview:** the Tailscale tab's route preview shows the merged list.
- **Approval:** new routes still need approval in the Tailscale admin console.

**Overall status** is *Degraded* only when *no* uplink is up. A wired device
with WiFi switched off stays *Online*.

> **Firewall note.** Firmware older than 0.1.20-W5500 attached the
> `TO_ESP` / `FROM_ESP` chains to WiFi only. On a wired device those rules were
> shown as active but did nothing. If you upgrade from such a build, review
> your rules.

API endpoints, all authenticated, body `{"enabled": true|false}`:

| Endpoint | Purpose |
|---|---|
| `POST /api/eth-uplink` | Ethernet *Use as uplink* switch |
| `POST /api/wifi-uplink` | WiFi *Use as uplink* switch |
| `POST /api/eth-routing` | Ethernet *Auto-route*. Optional `"cidr"` overrides the detected CIDR. |
| `POST /api/sta-routing` | WiFi STA *Auto-route* |

## Versions and OTA

Fork releases follow upstream's version number. The fork marker goes in SemVer
build metadata (`+W5500`):

| Release | Tag | GitHub release type |
|---|---|---|
| Test builds | `v0.1.28-beta1+W5500`, `v0.1.28-beta2+W5500`, ... | pre-release |
| Confirmed | `v0.1.28+W5500` | normal ("Latest") |

Under the firmware's version ordering (`main/ota.c`), these tags sort in the
right order without any code change:

- `beta1` < `beta2` < ... < the confirmed release.
- Every `0.1.28` build is newer than any `0.1.27` one.
- The `+W5500` suffix is ignored for ordering.

How devices pick up releases:

- OTA on this fork checks **this repository's** releases (`OTA_REPO_OWNER` in
  `main/ota.c`).
- **Stable channel** devices take only confirmed releases.
- **Beta channel** devices also take pre-releases. Use it on a test device to
  try the OTA flow.
- Every release carries `firmware.bin`, which OTA downloads, and
  `factory-full.bin`, for flashing a blank board over USB.

Never publish a plain upstream-numbered release (`v0.1.28`) here. It would
rank above `v0.1.28-beta1+W5500`, and devices would install firmware without
the Ethernet driver.

## Keeping up with upstream

The fork is upstream's `main` plus a small set of commits on top. Git history
is the source of truth for exactly what differs: `git diff upstream/main main`.

Where fork code meets upstream code:

| Touch point | Files |
|---|---|
| New files | `eth_uplink.c/.h`, `linker.lf`, this page |
| Ethernet event handling and uplink state | `main/main.c` |
| Uplink-agnostic routing | `main/lwip_route_hook.c` |
| Firewall, TTL and counters on the wired netif | `main/netif_hooks.c/.h` |
| Route composer (appended) and two marked call sites | `main/tailscale_manager.c`, `main/web_ui.c` |
| Status cards and the four endpoints | `main/web_ui.c`, `main/index.html` |
| Build and config | `main/CMakeLists.txt`, `main/Kconfig.projbuild`, `sdkconfig.defaults` |
| Two one-line identity changes | `OTA_REPO_OWNER` in `main/ota.c`; `PROJECT_VER` in `CMakeLists.txt` |

Steps when upstream releases (say v0.1.29):

1. `git fetch upstream`, then `git merge v0.1.29` on `main`.
2. `PROJECT_VER` always conflicts. Resolve it to `0.1.29-beta1+W5500`.
   Anything else that conflicts is in one of the touch points above.
3. Build, tag `v0.1.29-beta1+W5500`, and publish it as a pre-release with both
   binaries.
4. Test on a beta-channel device: the OTA update, the wired uplink, the tunnel.
   Fix problems as `beta2`, `beta3`, ...
5. Once it's confirmed, set `PROJECT_VER` to `0.1.29+W5500`, then tag and
   publish `v0.1.29+W5500` as a normal release.

Generic fixes go upstream as their own PRs first, so the fork stays small.

## Fork changelog

### [0.1.28+W5500] (in beta)

The fork was rebuilt on upstream v0.1.28 (including the SNMP agent) as a
compact layer:

- **SNMP is identical to upstream.** The fork's parallel copy of the SNMP
  history, its wording drift and its `web/` design notes are gone.
- **Three generic fixes were sent upstream** as
  [PR #12](https://github.com/Csontikka/esp32-tailscale-subnet-router/pull/12):
  URI-handler headroom, the favicon, and down-netif LAN bypass.
- **Route composition now builds on upstream's
  `tailscale_advertise_routes_effective()`** instead of replacing it. It reads
  the live Auto-route flags.
- **Fixed:** on a fresh board the Ethernet Auto-route showed *on* but advertised
  nothing until it was toggled. The old composer read the flag from NVS with an
  *off* fallback; `main.c` defaults it *on*.
- **Dropped:** the GCC 14 warning suppression in `CMakeLists.txt`. Upstream
  builds cleanly without it.
- **Fixed in beta2:** OTA over the wired uplink could crash `w5500_tsk`
  (`LoadProhibited`, `EXCVADDR 0`, inside `uninstall_priv_desc`). The cause was
  a failed per-transfer DMA bounce-buffer allocation, which ESP-IDF's cleanup
  then dereferences. The W5500 now uses an allocation-free SPI transport. The
  same crash was misread in 0.1.20-W5500.1 as a flash-cache problem, so every
  earlier fork release has it.

Releases up to 0.1.27-W5500.1 are recorded in the `CHANGELOG.md` at tag
[`pre-rebaseline-v0.1.27-W5500.1`](https://github.com/gszigethy/esp32-tailscale-subnet-router/blob/pre-rebaseline-v0.1.27-W5500.1/CHANGELOG.md).
