SYSTEM PAGE
===========

LAYOUT CONCEPT
──────────────
Single-column, card-per-section layout on all breakpoints.
Sections ordered by risk: safe config changes first, destructive actions last.
Danger zone card always at the bottom, separated by extra spacing.

NAV TABS (actual order in HTML)
──────────────────────────────
Status · Network · Tailscale · Firewall · Tools · System

SNMP AGENT — CARD DETAIL
─────────────────────────

Position: after Device card, before SD card logging.

Enable/Disable:
  Single checkbox: [☑] Enable SNMP agent
  Unchecking and saving stops the agent; the status badge goes to
  [Stopped] (badge-neutral). Checking and saving starts it; badge goes to
  [Running] (badge-success).
  Badge shown in card header right slot (same pattern as SD card logging
  and Firmware update badges).

Fields (all .input, not .input-mono — free-form printable ASCII):
  Community    max 255 chars  placeholder "public"
  sysName      max 255 chars  placeholder empty (or device friendly name)
  sysContact   max 255 chars  placeholder empty
  sysLocation  max 255 chars  placeholder empty

Info blurb (static, not collapsible — short enough to leave visible):
  ℹ Listens on all interfaces · UDP 0.0.0.0:161
    SNMPv1/v2c · read-only
    MIB-II (interfaces, IP, UDP) + Tailscale state,
    uplink, free heap, and per-core CPU OIDs

Footer:
  Right-aligned [Save] only. No secondary actions.

Save behaviour:
  POST /api/snmp — saves enabled flag + four NVS fields.
  Agent restarts in-place if currently running so the new community
  string takes effect immediately.
  JS re-fetches GET /api/snmp 2 s after a successful POST to update
  the header badge.
  [Save] button disabled until any field is dirty (same pattern as
  Device name and Web session cards).


SNMP API CONTRACT
─────────────────
  GET  /api/snmp  →  {
    "enabled":      true,
    "running":      true,
    "community":    "public",
    "sys_name":     "esp32-router",
    "sys_contact":  "",
    "sys_location": ""
  }
  POST /api/snmp  ←  same shape; omitted fields unchanged.

  /api/status should include:
    "snmp": { "enabled": true, "running": true }
  (consumed by status page if a future badge is added there).

  `running` may differ from `enabled` for a brief moment while the
  agent restarts. The 2-second re-fetch after Save closes that window
  for the user.


DANGER ZONE INTERACTION:
  All 3 actions → showConfirm() modal before any request is sent.
  Reboot → .btn-secondary (non-destructive restart).
  Clear password + Factory reset → .btn-danger (red).
  After confirm: spinner in place of button, POST to /api/reboot etc.
  On success: toast + (factory-reset) redirect countdown.

OTA UPLOAD FLOW:
  1. User selects .bin → filename shown in label span.
  2. [Upload & reboot] → XHR POST /api/ota-upload with progress bar.
  3. On success: card body replaced by reboot countdown + redirect.
  4. On error: inline error message, bar resets.

SD CARD BADGE VALUES:
  — (neutral)    no data yet
  Recording (success)
  Card missing (warning)
  Error (danger)

FIRMWARE UPDATE BADGE VALUES:
  — (neutral)    no data yet
  Up to date (success)
  Update available (accent/info)
  Error (danger)

WEB SESSION BADGE VALUES:
  Never (neutral)
  Active — HH:MM remaining (success when > 5 min, warning when ≤ 5 min)

MOBILE ADJUSTMENTS:
  All grid-cols-2 form groups collapse to 1 column.
  Danger zone buttons are full-width.
  Card header badges remain in the right slot on all breakpoints.
